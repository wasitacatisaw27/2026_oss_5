## Key Learning

1. querySelector로 HTML 요소를 찾고 addEventListener로 사용자 입력을 처리합니다.
2. createElement와 appendChild로 목록과 버튼을 만들 수 있습니다.
3. 배열을 변경한 뒤 render를 실행하면 변경된 데이터를 화면에 반영할 수 있습니다.

## CRUD Service

주제는 도서 관리입니다. 초기 데이터는 국어, 수학, 영어 3개입니다.

| Field | 설명 |
| --- | --- |
| id | 중복되지 않는 도서 번호 |
| title | 도서명 |
| author | 저자 |
| category | 카테고리 |
| price | 가격, 원 단위 |

입력창도 위 항목에 맞춰 5개를 사용합니다.

- Create: 입력값 검사 후 books.push로 도서를 추가합니다. 추가 후 입력창을 비웁니다.
- Read: render에서 목록을 비우고 for...of로 배열을 순회하여 li를 만듭니다. 처음 열었을 때도 실행합니다.
- Update: 수정 버튼을 누르면 기존 값을 입력창에 넣고 버튼 글자를 저장으로 바꿉니다. 저장할 때 동일한 입력 검사를 거쳐 해당 객체를 수정합니다.
- Delete: confirm에서 확인한 경우 splice로 배열에서 삭제하고 목록을 다시 출력합니다. 취소하면 유지합니다.
- 전체 삭제: 확인 후 배열을 빈 배열로 바꿉니다.
- 입력 초기화: 수정 중인 도서 선택을 해제하고 새 도서를 추가하는 상태로 돌아갑니다.

서버, DB, localStorage는 사용하지 않습니다. 새로고침하면 초기 데이터 3개로 돌아갑니다.

## Validation

추가와 수정은 같은 submit 함수에서 검사합니다.

1. 도서 id가 1 이상의 안전한 정수인지 확인합니다.
2. 다른 도서와 id가 겹치지 않는지 확인합니다.
3. 도서명, 저자, 카테고리가 공백만 있거나 비어 있지 않은지 확인합니다.
4. 가격이 0 이상의 안전한 정수인지 확인합니다.

검사 실패 시 alert로 알리고 해당 입력창에 focus한 후 return으로 종료합니다. 잘못된 값은 배열에 반영하지 않습니다.

## JavaScript

| 기능 | 사용한 곳 |
| --- | --- |
| querySelector | 입력창, 폼, 목록, 버튼 찾기 |
| addEventListener | load, submit, click 이벤트 연결 |
| preventDefault | 폼 제출 시 새로고침 막기 |
| createElement / appendChild | 목록 항목과 수정·삭제 버튼 만들기 |
| innerText | 사용자 입력을 HTML이 아닌 글자로 표시하기 |
| split / trim | 과일 입력을 쉼표로 나누고 양끝 공백 제거하기 |
| push | 배열에 도서 추가 |
| splice(i, 1) | 배열의 i번째 도서 한 개 삭제 |
| for...of | 각 도서 데이터를 차례로 읽기 |
| Number / Number.isSafeInteger | 숫자로 변환하고 정확히 표현 가능한 정수인지 검사 |
| render | 현재 배열을 화면에 다시 출력 |

editingBook에는 수정 대상으로 고른 배열 속 객체를 넣습니다. 그 객체의 속성을 변경하면 배열에 있는 도서 정보도 변경됩니다. null이면 새 도서를 추가하는 상태입니다.

과일 실습은 DOM 요소만 삭제하지만 도서 관리에서는 배열이 데이터 기준이므로 배열도 함께 변경해야 합니다.

## CSS

외부 my.css를 사용합니다. 아이디와 클래스 선택자로 배경색, 입력창 너비, 여백, 버튼 색을 적용했습니다. 수정 버튼은 파란색, 삭제 버튼은 붉은색이며 hover 시 색이 바뀝니다. 좁은 화면에서도 입력창이 화면 너비를 넘지 않도록 구성했습니다. 그림자와 가상 요소는 사용하지 않습니다.

## Problem & Solution

- 과일 코드의 전체 삭제에서 이벤트 객체에 remove를 호출하던 부분을 목록 내용 비우기로 수정했습니다.
- 과일 추가 후 입력이 남아 있어 value를 빈 문자열로 바꿨습니다.
- 배열을 화면에 출력만 하면 변경 사항이 보이지 않으므로 추가·수정·삭제 뒤 render를 호출했습니다.
- 수정 중인 도서의 번호는 자기 자신과 중복으로 판단하지 않도록 수정 대상과 비교했습니다.
- 수정 중인 도서를 삭제하면 입력창도 초기화하여 삭제된 객체를 계속 수정하지 않도록 했습니다.

## Reflection

화면의 목록과 배열은 별개이므로 데이터가 바뀔 때 화면 갱신도 필요합니다. 같은 폼을 추가와 수정에 함께 사용할 수 있고, 입력 검사도 공통으로 적용할 수 있습니다.
직접 실습한 뒤 어려웠던 부분과 새롭게 이해한 내용을 본인의 말로 보완합니다.

## 확인 결과와 직접 확인할 항목

코드 검사에서 초기 목록 출력, 추가, 잘못된 입력 차단, 수정, 삭제 확인·취소, 전체 삭제, 재추가와 초기화 흐름을 확인했습니다. 이 검사는 브라우저 화면을 직접 조작한 검사는 아닙니다.

브라우저에서 index.html을 열고 아래 내용을 확인합니다.

- 두 페이지 링크가 정상적으로 열리는지 확인
- 과일: apple, banana 입력 → 두 항목 추가 → 입력창 초기화 → 개별 삭제 → 전체 삭제
- 도서: 처음에 국어·수학·영어 3개 표시
- 추가: id 4, 과학, 저자, 교과서, 9000 입력 → 목록에 추가되고 입력창 초기화
- 검사: 빈 도서명, 중복 id, 음수 가격으로 추가·수정 시 반영되지 않음
- 수정: 수정 클릭 → 기존 값 표시 → 변경 후 저장 → 목록 갱신
- 삭제: 취소하면 유지, 확인하면 삭제
- 전체 삭제 후 다시 도서를 추가할 수 있는지 확인
- 창을 좁혔을 때 입력창과 목록을 사용할 수 있는지 확인
- 새로고침하면 초기 데이터가 다시 표시되는지 확인
